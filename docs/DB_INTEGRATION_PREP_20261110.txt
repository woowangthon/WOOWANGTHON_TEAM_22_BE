4. 실제 DB 적용 전·후 절차 — 이번 미실행

대상 프로젝트 불명,001~004 정의 불일치, 후보 객체 존재, 이력 불명, 백업 복구 가능성 미확인,

별도 승인 후 담당자 순서:
 1) 프로젝트·역할·service_role BYPASSRLS·private 버킷·정책·백업/복구 가능성을 확인한다.
    무료플랜 백업/PITR를 가정하지 않는다. 스키마/기존 회원·일기·원문·자산 ID/수량/체크섬과
    Storage 바이트를 접근 제한된 곳에 보관한다. metadata 수량은 바이트 백업 증거가 아니다.
 2) 확정/업로드/수정/구매 등 쓰기를 중단하고 기준 수량을 고정한다. A/B/C/D로 테스트하지 않는다.
 3) integration_preflight.sql로 실제001~004와 신규 객체 부재를 조회한다. 부분 적용이면 중단한다.
 4) 동일 연결에서 BEGIN; SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
    SET LOCAL lock_timeout='5s'; SET LOCAL statement_timeout='60s';
    room 전체→comic 전체→v0.4 전체 순으로 검토한 원문을 사용한다.
    v04_preflight는 room/comic 선행 객체가 필요하므로 동일 트랜잭션 중 v0.4 직전 조회용이다.
    이 조회를 위해 room/comic만 먼저 COMMIT하지 않는다. 기존 부분 상태는 별도 계획부터 세운다.
 5) 같은 연결에서 integration_verify+v04_verify와 원본 ID/체크섬/Storage 보존을 검사한다.
