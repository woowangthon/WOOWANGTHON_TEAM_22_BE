6. 실제 활성화 전에 정확히 남은 것
A. 영속 생성 요청 원장/원자적 claim: 회원+세션+revision+초안 기준으로 중복 접수 차단,
   원래 request_id와 확인 plan을 저장하고 worker 재시작·경합 때 같은 유료 생성 재실행 금지.
   local_runner는 메모리뿐이다. 제품 render_confirmed 자체에는 claim/멱등성이 없다.
B. 컷별 생성 바이트 checkpoint 및 실행기: 현재 render_confirmed는 모든 결과를 메모리에
   모은 뒤 persist_result로 넘긴다. 중간 종료/세션 소실/업로드·DB 장애 때 받은 바이트와
   원문/확인 증거를 보존·복구해야 한다. existing recover_result_uploads는 바이트가 있을 때만 유효.

   원장 상태·preview_id를 GET할 계약이 필요. unknown은 자동 재생성하지 않는 정책 유지.
   FE 첨부 응답 유실은 원래 키/preview_id를 sessionStorage에 보존하지만 자동 POST 재전송이나
   요청 영수증 기반 복구 UI는 아직 없다. 새 탭/브라우저 저장 삭제를 넘는 보호는 서버 원장 책임.
