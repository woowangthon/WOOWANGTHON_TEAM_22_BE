4. 보상·삭제·환불 중복 방지 결과

보상은 회원/서울 diary_date 최초 확정1건만30코인/1물방울이다.
삭제된 첫 확정도 자격 이력에서 유지하며, 지연된 최초 지급은 같은 sync로 복구 가능하다.
소급 보류된 첫 일기를 삭제하고 새 ID를 만들어도 해당 날짜 보류를 우회하지 못한다.
수정/삭제 API는 보상 RPC를 호출하지 않는다. 기존 확정 후 별도 sync 흐름/JSON은 보존했다.
지급 기록과 원본 FK는 남고, 삭제 후 같은 날 새 일기 ID가 생겨도 지급은1회다.
이미 지급한 보상을 삭제 때 자동 회수하지 않는 것이 이번 권장 후보이며 운영 전 확인 대상이다.

환불은 회원 잠금/지갑 잠금/활성 보유/배치 삭제/코인 가산/영수증 INSERT가 하나의 DB 함수에 있다.
같은 환불 키 재전송은 당시 응답 snapshot을 반환하므로 추가 반환/새 구매 취소가 없다.
새 키 환불도 보유가 없으면409. 재구매는 새 구매 영수증이며 다시1회만 환불한다.
다른 회원 보유/비보유는409, 보유 테마는422. 비활성 카탈로그 상품도 기존 보유라면 환불 가능하다.
구매 중 요청은 동일 회원 잠금 뒤 확정된 활성 보유만 검사한다. 미확정 보유를 미리 환불하지 않는다.

5. 이미지 저장·복구

실제 PNG/JPEG 검증/PNG 정규화/메타데이터 제거를 재사용한다.
원본 수신 바이트 hash+본문+expected_version으로 요청을 식별한다.
예약 DB(pending) → x-upsert=false 업로드 → 완료 DB(본문/활성 그림/버전/영수증 동시 전환).
이미 존재하는 객체는 실제 크기/hash를 확인한다. 불일치 파일은 완료 처리하지 않는다.
업로드/DB 실패 때 기존 활성 본문·그림·버전을 유지한다. 완료 커밋 뒤 응답 유실은 성공 여부 불명503이다.
같은키·같은본문·같은버전·같은파일 재전송으로 새 업로드/버전 증가 없이 복구한다.
완료 영수증 재전송은 당시 버전 결과를 반환하고 서명URL만 새로 발급한다.
서명 실패/잘못된 DB 성공 응답도200으로 표시하지 않는다.
pending 요청끼리 경쟁하다 버전 충돌이 나면 비활성 private 객체가 남을 수 있다.
DB와 Storage는 물리적으로 한 트랜잭션이 아니다. 자동 객체 삭제/만료 정책은 추가하지 않았다.
재시작 후 같은 파일 바이트가 필요하며 서버가 잃어버린 바이트를 자동 복원하지 않는다.

6. FE 전달 계약/적용 순서

  1) 상세 GET의 confirmed_text/edit_version/assets[0].imageUrl을 불러온다.
     그림판에는 활성 그림을 로드한다. URL은300초로 만료되므로 상세 GET으로 재발급한다.

     그림이 바뀐 때만 file을 넣는다. 결과가 불명확하면 본문/버전/키/파일을 바꾸지 않고 재전송한다.

  3) 삭제는 FE 예/아니오 확인에서 예를 선택한 경우에만 DELETE한다.
     아니오는 서버 요청 없음. BE가 실제 확인창 표시/사용자 클릭을 검증한 것은 아니다.
  4) 환불 버튼은 refundable/refund_coins를 사용한다. 금액은 FE가 보내지 않는다.
     새 구매/새 환불마다 새 키, 장애 복구에는 원래 키를 쓴다.
     오래된 환불 응답은 당시 snapshot이므로 재구매 뒤 owned/잔액의 현재값으로 사용하지 말고 room/shop을 재조회한다.
  5) 테마는 기존 구매→설정 PUT /api/me/room/theme, 기본은{"item_id":null}.
     환불 버튼은 제공하지 않는다. 배경/표지/성체 테마/기존 가구 좌표 동작은 그대로다.
  6) 만화 content_status=stale이면 이전 버전으로 만든 만화라고 표시한다.
     GET으로 새 생성/업로드를 시작하지 않는다. 진단 필드도 FE 검토할 후보이며 FE 코드는 변경하지 않았다.

OpenAPI에 multipart 필드·필수 DELETE 헤더·환불 모델이 노출된다. CORS If-Match를 허용한다.
현재 운영001~004만 있는 DB에 이 코드만 먼저 배포하면 새 열/RPC 부재로 실패한다.

기존 세션 preview URL/기존 서명 URL까지 즉시 철회하거나 개인정보를 영구 삭제했다고 설명하지 않는다.
